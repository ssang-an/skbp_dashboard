# 2026-09-16

## Changes

- Tab 2 재업로드 창에서 Tab 1 전용인 `업로드 없이 유사 이름만 저장` 일괄 동작을 숨기고, Full Scout의 신규 업로드와 이번 리포트로의 덮어쓰기만 안내. 기존 리포트 스냅샷 및 운영 정보 유지 범위를 명시.
- Asset·Company가 완전히 일치하고 기존 후보가 하나뿐인 재업로드는 검토 팝업 없이 이번 업로드 결과로 자동 덮어쓰기하도록 개선. `Unknown` 등 식별 불가 표기는 자동 갱신에서 제외.
- `src/app.js`, `index.html`: 데이터 재업로드 팝업의 일괄 덮어쓰기 버튼 라벨을 Tab1("표시된 항목 모두 덮어쓰기")/Tab2("표시된 항목을 이번 결과로 덮어쓰기")로 갈라져 있던 것을 "모두 이번 결과로 덮어쓰기"로 통일. 버튼 텍스트는 모달을 열 때 JS(`openDataReuploadModal`)가 매번 다시 설정하므로 `src/app.js`를 수정해야 실제로 반영됨(index.html의 초기 텍스트만 고쳤던 첫 시도는 무효였음). 안내 문구 내 버튼명 표기도 함께 갱신. 동작 로직은 변경 없음.
- `src/app.js`: 재업로드 검토 카드의 "유사 Asset/Company 이름도 함께 저장" 토글을 opt-in(기본 꺼짐, 눌러야 저장)에서 opt-out(기본 켜짐, "유사 Asset / Company 이름 저장됨"으로 표시되고 눌러야 "저장 안 함"으로 전환)으로 변경. 개별 덮어쓰기/제외 카드와 "선택 적용" 경로 모두 기본값이 저장으로 통일됨(`renderDataReuploadReviewList`, `reviewedDataReuploadDecisions`, `dataReuploadList` 클릭 핸들러). 일괄 버튼("모두 이번 결과로 덮어쓰기"/"업로드 없이 유사 이름만 저장")은 기존과 동일하게 항상 저장. 완전 정확 일치(Asset/Company 모두 exact) 자동 병합 경로는 저장할 새 표기가 없어 기존대로 저장 안 함 유지.
- Tab 1 재업로드에서 Asset이 정확히 일치하고 회사명이 확정 별칭으로 겹치면(P.S.K./PSK, 법인 접미사 유무, 저장된 괄호 별칭) Tab 0과 같은 기준으로 확인 창 없이 이번 결과를 자동 덮어쓰도록 정렬.
- 중단된 자동 갱신 검증 완료: 회사 별칭 판정의 접미사 규칙을 Tab 0에 맞추고 기존 입력·요약·저장된 회사 별칭을 비교에 포함. 자동 갱신 시 이전/새 이름 별칭 보존. 관련 테스트 20개 및 JS 문법 검사 통과; 모의 API를 사용한 Chromium에서 라이트/다크 대시보드·업로드 팝업 글자 표시 확인. 별도 Tab 0 기존 테스트는 Comment 표기·Contact 변환·Website 규칙 기대값 차이 6건 실패.
