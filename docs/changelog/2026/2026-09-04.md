- Added a read-only Disease Linkage O/X/— badge to the Shortlisting table, next to ADMET. Reads `scoring.criteria.moa_validity.investigation_note` directly (no Markdown parsing) and classifies it via a single small OpenRouter call (DeepSeek V4 Flash, same model as AI 2차 파싱, ~200 tokens in / 1 token out) into O ("disease-relevant linkage explicitly confirmed"), X ("explicitly not confirmed"), or NA ("insufficient information") — the call never reads or writes score/criterion values. Applies only to Full Scout v3.8+, non-Fast-Triage, tracked (Shortlisted) records with an *effective* `moa_validity` score of 2 or 3 (a manual score override is honored over the AI score); everything else renders "—" without calling the model. Result is cached per record in `meta.focus_management.disease_linkage_status` (+ the effective score it was computed from, a `score|note` hash signature, and a timestamp) — outside the Compact v2 JSON schema, matching how `in_vivo_status`/`admet_completed` are already stored — via a new `POST /api/records/{id}/disease-linkage-classify` endpoint, so the model is called at most once per distinct (score, investigation_note) pair. Deliberately *not* wired into the shared `GET /api/records` refresh path (would add unpredictable OpenRouter latency to every dashboard tab's load) or into record save/import (8 disparate call sites, risk of stalling bulk imports); instead the Shortlisting tab fires it quietly in the background per visible row after first paint and re-renders once results land — no blocking "잠시만 기다려주세요" modal, since each call is small/cheap and non-blocking. Ineligible rows (score 0-1, pre-v3.8, Fast Triage) are also cached as `NA` with the score they were checked against, so they aren't re-hit on every render either. Fixed same-day: a manual MoA Validity score override (`meta.human_review.overrides.scores.moa_validity`, which does not touch `investigation_note`) now invalidates the cache — the score is folded into the signature, `disease_linkage_score_used` is stored alongside the badge, and the frontend re-fires classification whenever `row.moaScore` (override-aware) no longer matches the cached `diseaseLinkageScoreUsed`, instead of leaving a stale O/X badge in place indefinitely (`main.py`, `src/app.js`, `src/styles.css`).
