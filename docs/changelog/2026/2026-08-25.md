# 2026-08-25

## Changes

- Full Scout Partner Materials 파일 카드 사이 여백과 상·하단 패딩을 소폭 줄여 여러 파일을 더 촘촘하게 표시했다.

- 과거 Tab 0 Contact History 동기화 형식(`listing_contact_post`)이 현재 형식과 중복 노출되던 문제를 정리했다. 동기화 시 과거 사본을 제거하고, 남아 있는 과거 사본도 Tab 0 원본 관리 항목으로 안전하게 인식한다.

- Partner Materials 파일명에서 `Non-confidential data`, `Confidential data`, `Due Diligence` 표현을 각각 NCDP, CDP, DD로 자동 감지하도록 보완했다. Non-confidential 표현은 CDP와 중복 분류하지 않는다.

- Due Diligence 상태의 DD pill을 파일 선택 창을 여는 업로드 동작으로 연결하고, 의견·자료 보유 pill의 라벨과 숫자 사이 간격을 통일했다.

- AI 2차 파싱은 입력 검토에서 실제 저장 불가 오류가 확인되고 Markdown 원문이 있을 때만 활성화되도록 제한했다. 경고만 있거나 저장 가능한 결과에서는 비활성화하며, 버튼 안내도 정상 결과의 불필요한 재파싱을 막도록 갱신했다.

- DD-labelled uploads from Partner Materials now route to the Team Review Due Diligence workspace with a `due_diligence` attachment source. The Team Review DD pill opens that uploader; a new DD file-count pill sits with the three opinion-status pills, and DD files are shown only after the Due Diligence section is expanded.

- Removed the redundant Partner Materials file-picker button; the click-and-drop upload area remains the single file-selection control.

- Full Scout Team Review Workspace now always uses overflow-aware internal scrolling. It remains visually scroll-free for short or collapsed content and becomes scrollable whenever its contents exceed the panel height.

- ADMET study mapping now recognizes standalone `BBB` as the canonical BBB penetration study. Recalculated the CK Regeon ADMET attachment from 8/25 to 9/25; qualified status variants such as `진행완료 (7d)` and `진행완료(H)` remain counted as completed.
- Simplified the Team Review comment-deletion confirmation, and removed the redundant Partner Materials availability label so its four compact pills remain on one line.

- Partner Materials now accepts every supported file without a category-selection confirmation. Compact NCDP, CDP, ADMET, and IR availability pills appear above the upload drop zone and light up only when a matching uploaded filename is detected.

- Contact History TXT previews and Agent extraction now detect UTF-8, UTF-16, CP949, and EUC-KR instead of assuming UTF-8. Office attachments without an existing preview are lazily converted to PDF, preserving PowerPoint/Word layout in the dashboard viewer while retaining the original file for download.

- Full Scout가 존재할 때 Fast Triage 작성자의 Final Comment·기준 메모·Contact History는 Tab 2에서 권한을 승계해 수정·삭제할 수 있게 했다. Tab 2 사본을 직접 분기하지 않고 Tab 1 원본을 갱신한 뒤 재동기화해 재업로드 시에도 내용이 갈라지지 않게 했다. Tab 0 원본 메모·Contact는 계속 Tab 0에서만 관리한다.

- Full Scout Contact History 첨부를 일반 filename 코멘트가 아닌 별도 파일 카드로 저장·표시하도록 분리했다. Contact 첨부는 Partner Materials에서 제외되며, 기존 filename 코멘트형 첨부도 Contact 파일 목록으로 호환 표시한다. 이미 파일 뷰어를 열었을 때 다음 파일을 선택하면 다운로드·원본 열기 기능이 있는 이동 가능한 보조 미리보기 창으로 연다.

- Tab 1·2의 Tab 0 동기화 Comment·Contact History를 더블클릭하면 원본 관리 안내를 표시하고, 확인 시 Tab 0의 같은 Pipeline·필드를 열도록 연결했다. 동기화 사본의 개별 삭제는 막아 원본과 Workspace 간 불일치를 방지한다.
- Tab 0 수기 Comment·Contact History에 작성자 계정 ID·이메일을 저장하고, 이름이 아니라 ID 우선·이메일 보조 기준으로 수정·삭제 권한을 확인하도록 강화했다. 기존 식별값 없는 수기 글은 다음 수정 전까지 작성자 이름 비교를 유지한다.
- Full Scout Contact History 파일 업로드 안내를 회의록·이메일 내용 파일까지 명확히 하고, 파일 뷰어가 GPT 원문/Team Review Workspace와 같은 하단 높이를 쓰도록 정렬했다. Fast Triage·Full Scout 상세 페이지에는 공통 한 줄 저작권·피드백 footer를 추가했다.

- Full Scout 완료 Pipeline은 Tab 0의 Fast Triage 단계에서 링크 없이 완료 표시만 보이도록 하고, Tab 1 상세 스크립트 캐시 버전을 갱신해 작성자 본인의 Contact History 삭제 UI가 최신 코드로 표시되게 했다.
- Listing 동기화 메모를 Tab 1·2에서 일반 코멘트 표기(`Tab 0 · Comment · 작성자 · 시각`)로 통일하고, 명시적인 Excel 가져오기만 `일괄 업로드`로 표시했다. 코멘트 소유권은 계정 ID 우선·동일 이메일 보조 방식으로 호환 처리했다.
- Listing 메모의 기존 `Team Review` 기본 표기를 `Team`으로 통일하고, Tab 0·1·2에서 동기화된 메모의 출처·작성자·시각 표시를 일관되게 정리했다.
- Wiki Map의 `표시할 항목` 및 `Node 연결 범위` 라벨·선택 영역에서 tooltip이 잘리지 않고 hover·키보드 초점 시 표시되도록 복구했다.
- Full Scout 상세의 Contact History·DD Report 파일 업로드 tooltip을 공통 대시보드 스타일로 유지하면서 카드·화면 경계에서 잘리지 않도록 위쪽·안쪽에 배치했다.
