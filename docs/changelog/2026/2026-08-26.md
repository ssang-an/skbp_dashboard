# 2026-08-26

## Changes

- Added shared Fast Triage and Full Scout identity/lifecycle early-stop instructions to avoid extended research after an unverified asset identity or a confirmed terminal Pipeline lifecycle. Pipeline Table now renders those schema-placeholder scores as `—` with a concise hover reason, while genuine assessed zero scores remain `0`.
- Added a startup-failure guard so an app-module initialization error clears the static loading shell and presents a visible, user-actionable error instead of leaving the Dashboard non-interactive.
- Fixed a Dashboard-breaking bug: the new early-stop instruction text embedded unescaped backtick pairs (`` `—` ``) inside a JS template literal in `src/app.js`, which terminated the literal early and threw `Uncaught SyntaxError: Invalid or unexpected token` on page load, leaving the entire Dashboard stuck on the static "Pipeline 데이터를 정리하고 있습니다" loading state with tabs unresponsive. Escaped both occurrences (`\`—\``); verified `node --input-type=module --check` passes and the page now loads and clears the loading state with no console errors.
- Released Fast Triage v3.4 and Full Scout v3.5: Target Relevance 3 now requires direct disease-biology linkage only (Theme/Cluster remains classification and exploration metadata), Fast Triage SELECT requires TR >=2, MoA >=1 and Data >=2, and Full Scout PASS requires total >=14, TR >=2, MoA 3, Data 3, with no hard blocker or decision-critical uncertainty. Updated the release manifest, prompts, compact-ingestion defaults, backend gates, display criteria, and detail-page labels together.
- Released Full Scout v3.6: PASS is now score-only (total >=14, TR >=2, MoA 3, Data 3); completed Full Scout assessments FAIL at total <=8 or when any of TR/MoA/Data is 0, otherwise REVIEW. Identity and confirmed terminal-lifecycle cases remain pre-research early stops, while server-side hard-blocker handling remains a safety guard.
- Corrected the remaining static Fast Triage judgment cards on the Dashboard and Fast Triage detail page to show the v3.4 SELECT gate (TR >=2, MoA >=1, Data >=2). Added a release-consistency test that checks visible Fast/Full gate text against the current rubric to prevent future manifest/UI drift.
- Refined only the Tab 2 REVIEW follow-up copy on the Dashboard and detail page to direct users to confirm additional public or internal evidence before re-evaluation; rubric and manifest versions remain unchanged.
- Clarified the visible Expansion Potential 3-point requirement as multiple additional indications, one official preclinical/IND-enabling/clinical program, and asset-specific quantitative data in at least one additional indication. Simplified the visible Fast Triage SELECT card by removing the identity and active-status bullets; those backend screening checks remain in force.
