# 10. 배포·영속성·동시접속 운영 검토

## 목적

서버 재배포/git pull 이후 계정이 유지되는지, 동일 서버 URL을 여러 사용자가 함께 사용할 수 있는지에 대한 현재 구조의 사실 기반 답변과 필요한 개선안을 남긴다.

## 작업

- 사용자/세션/권한 데이터의 실제 저장 위치와 배포 플랫폼의 디스크 영속성을 확인한다.
- 단일 JSON 저장소의 동시 쓰기 위험, 다중 worker/인스턴스 동작, 세션 공유 여부를 점검한다.
- 동일 서버 주소 동시 접속 가능 여부와 제약을 설명한다.
- 운영에 필요한 영속 볼륨·DB·백업·secret 관리의 최소 권고안을 비용/복잡도와 함께 제안한다.

## 산출물

- 코드 변경 없이 이 파일의 `## 검토 결과`에 질문별 답변과 근거를 기록한다.

## 완료 기준

- 계정 재등록 필요 여부와 이유가 명확하다.
- 동시 접속의 가능 범위 및 데이터 충돌 위험이 명확하다.
- 인프라 변경이 필요하면 별도 구현 작업의 범위를 제안한다.

## 검토 결과
