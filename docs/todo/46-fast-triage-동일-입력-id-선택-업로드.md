# 46. Fast Triage 동일 입력 ID 선택 업로드

## 목적

한 번의 Fast Triage 업로드 안에서 서로 다른 원문 행이 정규화 후 동일한 저장 ID가 되는 경우, 서버 오류로 끝내지 않고 사용자가 유지할 행을 선택할 수 있게 한다.

## 작업 범위

1. FastAPI 사전 검증 응답에 중복 저장 ID와 원본 행 번호를 포함한다.
2. 기존 Pipeline 비교 모달에서 동일 입력 행을 별도 검토 대상으로 표시한다.
3. 사용자가 한 행을 선택하면 나머지 행은 이번 저장에서만 제외한다.
4. 기존 저장 Pipeline과의 유사/덮어쓰기 검토는 기존대로 이어서 수행한다.
5. 서버 저장 경계의 중복 차단은 유지하고 회귀 테스트를 추가한다.

## 완료 기준

- NG201처럼 동일 ID로 정규화된 두 Fast Triage 행에서 유지할 한 행을 선택해 저장할 수 있다.
- 직접 API로 중복 행을 저장하려 하면 기존처럼 차단된다.
- 기존 레코드 덮어쓰기 선택 흐름이 유지된다.
