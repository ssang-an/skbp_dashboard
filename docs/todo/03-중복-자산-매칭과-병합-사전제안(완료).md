# 03. 중복 자산 매칭과 병합 사전 제안

## 제안 결과

현재 `main.py`의 `asset_aliases_from_text`/`company_aliases_from_text`와 `dashboard_identity_groups`가 공백·구두점·법인 접미사 정규화 및 별칭 중첩으로 Fast Triage와 Full Scout를 묶는다. 이는 read-only dashboard grouping이며 레코드를 병합하지 않는다. `IL01`과 `IL-01`은 대응 가능하지만, leading zero를 제거하지 않으므로 `IL001`은 별도 후보가 된다.

### 안전한 매칭 정책

1. 자동 병합은 하지 않는다. 업로드 시에만 후보를 보여 주고 사용자가 선택한다.
2. **강한 후보**: 회사 alias가 정확히 일치하고, 자산 alias가 case/공백/하이픈 제거 후 동일하거나 영문+숫자 토큰의 선행 0만 다른 경우. 예: `IL-01`, `IL01`, `IL001`.
3. **경고 후보**: 회사가 동일하고 자산 edit-distance 유사도 0.88 이상(짧은 이름은 1 글자 차이 이하)인 경우. 이 결과는 자동 선택하지 않고 ‘유사 이름’으로 표시한다.
4. 회사가 다르거나 generic asset명만 같은 경우는 후보로도 자동 제시하지 않는다.

### 2단계 UI 및 병합 매트릭스

1단계는 후보의 Asset, Company, Stage, 매칭 근거를 스크롤 목록으로 보여 주고 `새 레코드`, `기존 항목에 병합`, `건너뛰기`를 선택한다. 2단계는 `전문 보고서`, `structured_table`, `첨부`, `전문 보고서 메모`, `Team Review`를 각각 **새 값으로 대체 / 둘 다 보존 / 기존 유지** 중 선택하게 한다.

- 새 레코드: 기존 데이터 불변.
- 건너뛰기: 업로드 결과와 기존 데이터 모두 불변.
- 병합: structured data와 전문 보고서는 선택한 한쪽만 활성값으로 두고, 첨부·메모·Team Review는 기본적으로 union/append 보존한다. 삭제는 허용하지 않는다.
- 모든 병합은 기존 레코드 snapshot, 선택값, 시간, actor를 audit trail에 남기며 UI에서 직전 병합 되돌리기를 제공한다.

구현 영향은 `main.py`의 후보 API/원자적 병합/audit, `src/app.js`의 업로드 전 모달, `index.html`/`styles.css`, API unit test다. 전체 실행 승인에 따라 이 정책으로 04를 진행한다.
