# 10. 배포·영속성·동시접속 운영 검토

## 검토 결과

- 계정은 `data/users.json`, 분석 데이터는 `json/pipeline-records.json`, 첨부는 `attachments/`에 저장된다. 로컬 실행 또는 영속 디스크가 붙은 단일 서버에서는 유지된다.
- Render/Railway 등의 기본 ephemeral disk에 배포하면 재배포·인스턴스 교체 후 해당 파일들이 사라질 수 있으므로, 계정을 다시 가입해야 할 수 있다. Git pull 자체는 파일을 삭제하지 않지만 배포 과정에서 새 컨테이너가 만들어지면 영속성은 보장되지 않는다.
- 한 URL에 여러 사용자가 동시에 접속하는 것은 가능하다. 다만 현재 JSON 파일 저장은 단일 파일 원자적 교체 방식이라, 여러 worker/인스턴스가 동시에 같은 레코드를 수정하면 마지막 저장이 앞선 변경을 덮을 수 있다.
- 최소 운영 구성은 단일 worker + 영속 볼륨 + 정기 JSON/첨부 백업이다. 다중 인스턴스, 고가용성 또는 동시 편집을 지원하려면 사용자·레코드·첨부 메타데이터를 PostgreSQL 같은 DB로 이전하고 object storage를 사용해야 한다.
- 세션은 `data/users.json`의 해시 토큰으로 관리된다. 같은 영속 볼륨을 공유하는 단일 서비스에서는 유지되지만, 인스턴스별 로컬 파일을 쓰는 수평 확장에서는 공유되지 않는다.
