# 05. 역할 기반 접근제어와 회원관리 구현

## 목적

`user < admin < developer` 3단계 권한과 지정 관리자 계정, 사용자/권한 관리 화면을 안전하게 도입한다.

## 작업

- 현재 로그인·세션·비밀번호·관리자 판별·JSON 보기 로직과 배포 시 영속성 제약을 먼저 확인하고, 승인된 저장/인증 방식을 적용한다.
- 이름과 이메일이 모두 일치할 때만 초기 admin 권한을 부여한다. 이메일은 `@` 앞부분을 대소문자 구분 없이 비교하고 허용 도메인을 적용한다.
- developer는 admin 권한을 상속하도록 단일 역할 모델로 구현하고, 기존 JSON 보기 권한을 developer까지 유지한다.
- 권한 없는 사용자가 가능한 기능(메모, AI chat, Team Review 코멘트, Tab 1·2 업로드 및 중복 감지)과 admin 전용 변경 기능을 API와 UI 모두에서 강제한다.
- developer 전용 설정/디버그 기능은 코드베이스 조사 후 목록화하여 최소 권한으로 분류한다.
- developer용 Members 페이지에 계정·이름·이메일·역할을 보여주고 권한 부여/수정을 제공한다. 비밀번호 평문 표시는 하지 않고, 요청된 ‘확인’ 목적은 안전한 재설정/관리 흐름으로 구현한다.
- 로그인 비밀번호 찾기는 개발자 문의 안내만 제공한다.
- 권한 상승·직접 API 호출 차단·세션 만료 등 보안 테스트를 작성한다.

## 완료 기준

- API와 화면 양쪽에서 권한이 일관되게 적용된다.
- 지정된 7명만 이름+이메일 일치 시 admin이 되고 developer는 별도 상위 역할로 동작한다.
- 민감 정보가 평문 저장·노출되지 않는다.
- 단일 목적 Git 커밋을 남긴다.
