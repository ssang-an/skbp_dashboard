# 03. 중복 자산 매칭과 병합 사전 제안

## 목적

`IL01`·`IL001`·`IL-01` 같은 표기 차이로 인한 중복 상세 페이지를 방지하기 위한 유사 매칭·병합 정책을, 데이터를 변경하지 않고 제안한다.

## 작업

- 현재 record key, identity group, canonicalization 및 후보 큐의 중복 처리 로직을 조사한다.
- 회사명과 자산명 각각의 정규화 규칙(공백·하이픈·leading zero 등)과 오탐 위험을 정리한다.
- ‘회사 동일 + 자산 정규화 동일’의 자동 후보, edit distance 등 약한 신호의 경고 후보를 구분한다.
- 업로드 전 2단계 모달 UX를 설계한다: (1) 매칭 대상 선택, (2) 새 보고서·구조화 데이터·첨부 파일·전문 보고서·메모·Team Review Workspace의 보존/병합 방식 선택.
- 스킵·병합·새로 생성 시 결과와 되돌리기/감사 로그 필요성을 명확히 한다.

## 산출물

- 코드 변경 없이 이 파일의 `## 제안 결과`에 매칭 규칙, 임계값, 병합 매트릭스, 영향 파일을 기록한다.

## 완료 기준

- 자동 병합을 하지 않는 안전한 기본값과 사용자 확인 지점을 정했다.
- 보존 필드와 대체 가능 필드를 구분했다.
- 사용자가 04의 판정 기준과 병합 옵션을 승인했다.
