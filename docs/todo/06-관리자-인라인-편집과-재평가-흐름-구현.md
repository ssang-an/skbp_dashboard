# 06. 관리자 인라인 편집과 재평가 흐름 구현

## 목적

관리자가 Tab 1·2·3에서 stage·target·score 관련 값을 안전하게 수정하고, 최신 자료를 반영한 재평가 상태를 알 수 있게 한다.

## 작업

- 현재 canonical stage 목록을 코드·스키마·UI에서 조사해 확정 목록과 순서를 문서화한다.
- admin 전용 stage dropdown 및 Tab 2의 `Unknown` target 직접 수정 UI를 추가하고 서버 검증을 둔다.
- 기존 score 수정 규칙과 동일하게 score/filter 변경 시 rubric 버전, total score, hard filter, Tab 3 동기화가 일관되도록 한다.
- 재평가가 필요한 레코드 상태와 실행 중 spinner, 완료 후 원복, 실패 메시지를 구현한다.
- GPT 전문 보고서(메모 포함)와 Partner Materials를 재평가 컨텍스트에 포함할 수 있는지 현재 API/데이터 구조로 검증하고, 불가능한 부분은 명시한다.
- 지침 복사·업로드 완료·병합 완료 등 성공 피드백을 일관된 pill/toast 상태로 제공한다.
- 역할별 편집 차단과 Tab 2→Tab 3 반영을 테스트한다.

## 완료 기준

- admin만 해당 값을 수정할 수 있고 user는 읽기 전용이다.
- 재평가·업로드 상태가 취소/성공/실패 모두에서 명확하다.
- stage 및 score 변경이 연관 테이블에 정확히 반영된다.
- 단일 목적 Git 커밋을 남긴다.
