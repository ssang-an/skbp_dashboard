# 05. 역할 기반 접근제어와 회원관리 구현

## 완료 내용

- `user < admin < developer` role rank와 상속 판정을 서버에 추가했다.
- 신규 가입 시 이름과 확정된 전체 이메일 주소가 초기 OI-team allowlist와 정확히 일치할 때만 admin/developer role을 부여한다. 이메일은 대소문자를 구분하지 않으며, 7명 각각의 `skbp.com`/`sk.com` 주소만 허용한다.
- session response는 role, `is_admin`, `is_developer`를 반환한다. 비밀번호는 PBKDF2 hash/salt만 저장·노출하지 않는다.
- Developer만 `/admin/users` 및 회원 목록/역할 변경 API에 접근한다. 자기 자신의 developer 권한을 낮추거나 비활성화할 수 없다.
- Members 화면에서 user/admin/developer 역할을 확인·변경할 수 있고, 기존 활성/비활성 관리와 audit event를 유지한다.

## 검증

- role hierarchy, 전체 이메일 대소문자 정규화 및 명단 일치, Python compile, JavaScript syntax와 `git diff --check`를 검증했다.
