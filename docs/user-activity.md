# 사용자 활동 조회

- 사용자 관리 API와 화면은 Developer 계정 전용이다. 최근 접속 순으로 표시하며 화면이 보이는 동안 15초마다 갱신한다. 사용자가 권한 선택 상자를 조작하는 중에는 자동 갱신을 미룬다.
- 브라우저는 로그인 후 페이지 접속과 활성 신호를 `/api/auth/activity`로 보낸다. 성공 응답은 해당 서버의 `data/users.json` 저장 완료 후 반환하며 계정 ID와 기록 시각을 포함한다.
- 목록 상단의 주소·서버 이름·식별값은 조회 범위를 구분한다. 같은 서버의 다른 접속 주소는 같은 파일을 읽지만, 각 PC에서 별도로 실행한 서버는 사용자 파일이 서로 다르다. `git pull`은 사용자 기록을 동기화하지 않는다. 팀 전체 기록을 모으려면 같은 서버 URL을 사용한다. 사용자 파일에는 인증 정보가 있으므로 Git에 추가하지 않는다.
- `10.*`는 사설 IP이며 사용자 신원을 뜻하지 않는다. 활동은 로그인 계정에 귀속된다. `actor_ip`는 기존 전달 헤더 우선 규칙을 따르고 `peer_ip`는 실제 서버 연결 IP를 보관한다. 프록시 환경에서는 둘이 다를 수 있으며 IP만으로 사람을 확정하지 않는다. `Shutting down`은 서버 종료 로그이다.
- 상세 이벤트는 사용자별 최근 2,000건까지만 보관한다. 과거 이벤트 삭제나 다른 서버에 저장된 기록은 이 화면에서 복원할 수 없다.
- 활성 시간은 브라우저가 화면 표시·최근 상호작용을 기준으로 보내는 신호의 추정치이다. 요청당 최대 120초, 계정별 직전 신호 이후 경과 시간 이내로 제한하여 동시 탭의 중복 집계를 줄인다. 첫 신호는 시계만 초기화한다. 실제 근무 시간이나 정확한 체류 시간을 의미하지 않는다.
- 이번 변경 전에는 서버가 활성 초를 저장하지 않았다. 과거 시간은 추정하여 채우지 않고 `미수집`으로 표시한다. 적용 후의 부분 집계에도 수집 시작 시각을 함께 표시한다.
- 새 일별 집계는 한국 시간 기준 최근 100일을 유지하고 활성 시간 총계는 별도로 누적한다. 30일 접속자는 보관된 접속 이벤트와 일별 집계에 근거하므로 과거 보존 범위의 영향을 받는다. CSV의 미수집 시간은 빈칸이다.
- 각 서버에 코드를 적용하고 재시작해야 변경이 작동한다. 여러 프로세스나 여러 서버가 동시에 쓰는 공용 저장소로 전환하려면 별도 DB 및 동시성 설계가 필요하다. 현재 JSON 저장은 단일 서버 프로세스 운영 기준이다.
