# 대시보드 기능 점검 — 2026-09-14

현재 작업 트리와 로컬 서버를 대상으로 자동 테스트, 실제 Chromium 브라우저 조작, HTTP API 및 라우팅 검사를 수행했다. 재현된 기능 결함과 화면 폭 문제를 수정했고, 변경 영역 회귀 테스트 62개를 통과했다.

## 확인하고 수정한 결함

| 우선순위 | 기능·재현 조건 | 원인과 영향 | 조치·검증 |

실행 중인 기존 8000 포트 서버는 코드 변경을 자동 반영하지 않았다. 해당 서버를 재시작해야 위 수정이 실제 사용 화면에 반영된다. 점검 중 기존 서버를 종료하거나 재시작하지 않았다.

최초 브라우저 실행에서는 샌드박스가 CDN 요청을 차단했다. 네트워크 접근이 가능한 점검 실행에서는 외부 그래프 라이브러리가 로드됐고 Wiki Map이 동작했다. 이 최초 차단은 제품 자체 결함으로 집계하지 않았다. 브라우저 로그인은 테스트 응답을 사용했으므로 실사용 계정의 로그인 성공 검증과는 구분한다. 브라우저에서 변경 API 요청은 차단했고, 실제 데이터 저장·삭제·계정 변경은 수행하지 않았다.

## 자동 테스트 결과와 남은 점검 항목

- 최초 전체 실행: `python -m unittest discover -s tests -v` — **546개 실행, 실패 61건, 오류 4건**. 서브테스트 실패를 포함한 unittest 집계이며 기능 고장 65개를 의미하지 않는다.
- 수정 후 관련 회귀 실행: `tests.test_api_routing`, `tests.test_listing_website_validation`, `tests.test_listing_import_feedback`, `tests.test_auth_admin`, `tests.test_shortlisting_project_permissions` — **53개 통과**. 이 중 새 회귀 테스트는 5개다.
- 전체 테스트를 통과로 만들기 위해 현재 기능을 과거 문구나 정책으로 되돌리지는 않았다. 수정 후 전체 546개를 다시 실행한 결과는 아니며, 관련 회귀 테스트의 통과와 구분해야 한다.
- 기존 실패·오류의 45건은 `test_dashboard_ia`에 집중된다. 과거 Fast Triage/Full Scout 문구, 특정 캐시 버전, 이전 마크업·구현 문자열을 기대하는 사례가 다수다.
- `test_step0_progress_summary_shows_recent_fifteen_day_upload_increases_on_cards_only`는 테스트 자체에서 정의되지 않은 `load`를 사용해 `NameError`가 발생한다.
- `test_render_compatibility`의 2건은 DOM 모형에 `addEventListener` 또는 `getAttribute`가 없어 실패한다. 실제 브라우저의 해당 화면 로드에서는 같은 오류가 재현되지 않았다.
- 저장 데이터와 과거 Git 기준 데이터를 동일하게 요구하는 검사, Website 입력 정책, Modality 병합 우선순위, 수동 점수 변경 이력 순서 등은 현재 정책에 맞는 기대값인지 검토가 필요하다. 단순 문구 검사 실패와 동작 계약 불일치를 나누어 정리해야 한다.
- 기존 테스트 중 외부 번역 호출은 네트워크 오류 후 대체 처리로 통과한 경우가 있다. **실제 OpenRouter AI 응답 성공을 검증한 것으로 해석하면 안 된다.**

## 이번에 실사용까지 확인하지 않은 범위

실제 사용자 자격 증명으로 로그인·가입·비밀번호 재설정 메일 발송, 외부 AI 채팅·재평가·번역 성공, 실제 파일의 업로드·저장·삭제, 모든 첨부 파일 형식의 변환·미리보기, 전체 필터 조합 및 모바일 브라우저는 실사용 통합 검증을 수행하지 않았다. 관련 자동 테스트가 있더라도 이 범위의 실사용 성공을 보장하지 않는다.
